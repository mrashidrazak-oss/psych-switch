# PsychSwitch — developing on Windows

How to set up and continue PsychSwitch development on a Windows PC.
Everything needed is in this GitHub repo; a few machine-specific files
(keystore, `key.properties`) are deliberately **not** in git and are
only required for *release* builds — see step 4.

## 1. Install the tools (one-time)

1. **Git for Windows** — https://git-scm.com/download/win (accept the
   defaults).
2. **Android Studio** — https://developer.android.com/studio — installs
   the Android SDK, `adb`, an emulator, and a bundled JDK.
3. **Flutter SDK** — https://docs.flutter.dev/get-started/install/windows
   — unzip to a short path such as `C:\src\flutter`, then add
   `C:\src\flutter\bin` to your **PATH** (Settings → "environment
   variables" → edit Path).
4. **VS Code** + the **Flutter extension** — recommended editor.
5. **Enable Developer Mode** — run `start ms-settings:developers` and
   turn it on (Flutter needs it for plugin symlinks).
6. In a fresh terminal run **`flutter doctor`**, fix anything flagged,
   and run `flutter doctor --android-licenses` to accept the Android
   licences.

## 2. Get the code

```
git config --global core.longpaths true
git clone https://github.com/mrashidrazak-oss/psych-switch.git
cd psych-switch\flutter_app
flutter pub get
```

- `core.longpaths true` avoids Windows path-length errors with
  Flutter/Gradle.
- The repo is private — sign in to GitHub in the browser popup when
  `git clone` prompts.
- Firebase works out of the box: `lib/firebase_options.dart` and
  `android/app/google-services.json` are committed.

## 3. Run it

- Start an emulator (Android Studio → Device Manager) **or** connect an
  Android phone with USB debugging enabled.
- `flutter run`

**Google sign-in note:** each computer has its own *debug* keystore, so
to test "Continue with Google" on this PC you must add this machine's
debug SHA-1 to Firebase. Get it with `cd android && gradlew
signingReport`, copy the debug variant's SHA-1, and add it at the
Firebase console (Project settings → Your apps → Add fingerprint). Not
needed for general development — only for testing sign-in.

## 4. Release builds on Windows (only when needed)

`android/key.properties` and the upload keystore hold signing secrets
and are **not** in git. For a *release* build:

1. Copy `psychswitch-upload.jks` from your backup to e.g. `C:\keys\`.
2. Create `psych-switch\flutter_app\android\key.properties`:
   ```
   storePassword=yourpassword
   keyPassword=yourpassword
   keyAlias=upload
   storeFile=C:/keys/psychswitch-upload.jks
   ```

Without this file the build falls back to debug signing automatically —
fine for day-to-day development.

## 5. Daily workflow

```
git pull            # before starting
# ...make changes...
git add <files>
git commit -m "..."
git push
```

The **`main`** branch is the trunk and has everything.

## What is NOT in git (by design)

| File | Why | Needed for |
|------|-----|------------|
| `android/key.properties` | holds the keystore password | release builds only |
| `psychswitch-upload.jks` | the signing private key | release builds only |
| `android/local.properties` | machine-specific SDK paths | auto-generated by Flutter |

## Verifying a healthy checkout

```
flutter analyze      # expect: No issues found
flutter test         # expect: all tests passing
```
